## Scope rule (lane F)
- `options` = the `useFamilyPeople` people whose id is in `usePeople()` (rows RLS lets this phone read) minus `kind === 'shared'`; cached sign-in names alone never list a person. While acting (View as): the acting person is selected and the list is `useViewedVisibleIds`.
- `// shortcut:` comment on that rule: a non-owner admin would list everyone their RLS shows; no such login exists (plan 3.3 A), upgrade with part 2.
- `selectedId` survives Family's own pages (member page, back) and clears when the hash leaves `#family`, on sign-out and on every open. Nothing is stored in kv or localStorage. Module-level state with a hash listener is fine; test it.
- Pill and sheet copy from the boards: "Who to show", sections "You care for" and "Everyone else (only your account sees these)", "Family opens on Me every time."

## Sync rules (lane Y)
- `pullPeople`: `archived_at=is.null`, always keeping the caller's own row, even if archived. Selects `kind`; on 42703 falls back without it, then to the existing names-only read, so an unapplied migration keeps working.
- The purge also runs on a successful empty read. It never runs on a failed read and never purges the caller's own row.
- A newly seen person id clears the pull cursors and runs the tables once more in the same sync. No duplicates (merge keys on `client_id`).
- One-shot cursor reset on the owner's phone only, kv key `sync.d109CursorReset`; runs once, spent after a successful pull. Depends on 0046 being applied first: that is the release order.
- `activity` gets `cursor: 'updated_at'`; merge updates a known row only for sensor hours and only when the total rises. Remove the `shortcut:` comment in `sensors/health.ts`. Today's cursor falls back to `created_at` on 42703.

## Invariants
- Never zero owners; never two. A failed read never reads as "not linked" or wipes data. Self is always shown. Unknown is null.
- No other person's data on the default Family page except two things. (1) A writer carer's "Name: missed a medicine", with no medicine name or number, and it opens that person. (2) A live storm roll call (a PAGASA wind signal): it lists everyone this phone knows, with safe or no answer, by the family-wide safety rule; the shared family account is not listed or counted on the owner's phone. Known limit: other phones still list it, because the sign-in list has no kind.
- Read-only viewers and the owner get no flags or alerts for people they are not writer carers of.
- dose-watch and `notify_family` scope stays `can_write`.
- Old bundles keep working after 0046: `'added'` reads as `'unchanged'`.
