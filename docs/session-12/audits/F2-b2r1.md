# Lane F2 audit round 1 (batch 2, Opus): pass_with_issues

1. [major] (ML-37 spec) No screenshots exist for any of the six mockup screens the brief names (learn-meds, learn-medcard, learn-suppcard, learn-recipes, learn-recipe, learn-cook), and none were compared with the mockup. The builder lists these known gaps: no Listen or Ask Jack buttons, no diagram on the medicine card, no dish picture, no 'Add to meal log', no per-person 'Mama's medicines', and a fixed 1,500 mg salt limit. The builder disclosed this (ML-37 ok:false). Until the shots are made and checked, the UI does not show it matches the v6 mockup.
2. [minor] (ML-17 tests) PLAN 4.1 asks for a 'bundle growth <= 3 MB (vitest on dist size)' test. learn.test.tsx only checks the length of JSON.stringify([MEDCARDS, RECIPES]). That leaves out the JS/CSS chunk growth and never measures dist.
3. [minor] (ML-25 tests) The builder marked ML-25 ok, which is false. In e2e/s12-learn.spec.ts, the test 'Learn pages fit at 360 px' does page.waitForTimeout(150) after each goto and then checks scrollWidth. It never waits for a settled test id, so the check can run before the sub screen renders and pass with nothing on screen.
4. [minor] (NEW gate) articleText(id) in pick.ts, which index.ts re-exports, returns the full text of medicine and supplement cards whether or not kv learn.medcards is on. Only the routes in Screen.tsx check the flag. If F4's SpeakButton or any other consumer calls it outside the gated routes, it can read out cards the clinician has not signed.
5. [minor] (ML-12 copy) The recipe source line says sodium is 'an estimate from USDA FoodData Central values'. The builder admits the values are remembered, not looked up. They are plausible on spot check (1 tsp patis 470 mg, 1 tsp bagoong 450 mg). Recipes ship with no flag or clinician gate, so the source claim is not verified. Also, the malunggay card's forWhat is 'Leaves, powder or capsule', which is a form, not a use, and SuppCard shows it under the 'Herbal supplement.' lead line.
6. [minor] (ML-03 merge) The shared F1 file src/features/discover/index.ts got more than a one-line hook. registerSub and subScreen moved into a new src/features/discover/registry.ts and are re-exported from index.ts. The fix is correct and needed: hoisted `import './learn'` ran registerSub while `subs` was still in the TDZ. `export ... from './registry'` comes before the side-effect imports, so registry evaluates first. The builder disclosed it. The orchestrator must keep the re-export when merging the F3/F4 import lines.
7. [minor] (ML-04 spec) The contract asks for a 'credits entry in src/features/docs/*'. It was not added, because that folder is the scan-documents feature. Credits appear only as per-page source lines. The DailyMed/openFDA, NIH ODS, USDA FDC, Pinggang Pinoy and DASH lines are still owed in docs/SOURCES.md (F4 file). The builder disclosed this in needs.
8. [minor] (NEW other) Cook.tsx renders role=dialog aria-modal=true through a portal on document.body. It does not move focus into the dialog, does not trap focus, and has no Escape handling. The app frame behind it stays in the tab and screen-reader order, so a keyboard or TalkBack user can land on controls the overlay hides.
9. [minor] (ML-04 spec) The release-gate mechanism is incomplete. learn.medcards is a local-only Dexie kv key with default false, no admin toggle and no server sync. After the clinician signs off, the cards can only be turned on per device by hand or by a code change and a new APK release. The builder disclosed this in needs.
10. [minor] (ML-07 privacy) Meds.tsx lists every live ldb.medications row on the phone under 'Medicines on your family's lists'. It does not filter to people the phone knows or skip archived people, so leftover rows for an archived person can still show. No new server read is involved. The builder disclosed this.
11. [minor] (ML-20 other) Full vitest exits 1 in the lane worktree, but the lane code is not the cause. The worktree's node_modules is an empty directory, so the ../../../node_modules ?raw imports in pushManifest.test.ts and sensors.test.tsx fail to resolve. The same two files pass on base c520f6e in a nested worktree that has node_modules (exit 0, 45 tests). carer-cards.test.tsx also failed once during the 684 s full run and passed alone (exit 0, 24 tests), so it looks like a load flake in a file the lane did not touch.
