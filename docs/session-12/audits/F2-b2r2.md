# Lane F2 audit round 2 (batch 2, Opus): pass_with_issues

1. [major] (NEW regression) Cook.tsx: the new useEffect sets `inert` on #root before the `if (!r)` early return. So for an unknown recipe id (#discover/learn/cook/<bad-id>, which Screen.tsx routes to Cook for any id), the fallback 'We do not have that recipe' card and its 'Back to recipes' link render inside #root and are inert. The tab bar and Jack button are inert too. The whole app is locked until browser or hardware back. This came in this round and no test covers it. Fix: skip the effect when r is undefined, for example by gating on r, or set inert only inside the portal branch.
2. [major] (ML-37 spec) The lane brief's one major is only partly closed. ML-37 says to scroll to the feature. The shots capture only the first viewport, because fullPage does not include the inner scroller. On medcard, suppcard and recipe, the lower sections (Do not mix with, doctor line, sources, ingredient list, steps) were never shot or compared by eye. Example: learn-recipe-light.png ends at the first two ingredients. The builder disclosed this as ML-37 ok:false. A scrolled second shot per screen was cheap and was not done.
3. [minor] (ML-25 tests) ML-25 is marked ok, which is false. The 360 px spec now waits on `.lr` first visible after each page.goto, but every Learn screen, the home included, has class .lr. A hash-only goto does not reload the page, so the old screen's .lr already matches and the scrollWidth check can still run before the new sub screen renders. It should wait on each route's own test id (medcard, recipe, recipe-card...) the way the shots test does. ML-25 also asks for a --repeat-each proof under 2 and 4 workers, and that proof was not run.
4. [minor] (ML-02 contract) contracts.md line 85 says `articleText(id: string): string | null`. Calls written to that signature now get null for every medicine, supplement and herbal card, because medcards defaults to false. The added parameter is optional, so it type-checks, but the meaning changed without a contract update. It is listed in needs for F4. The orchestrator must update contracts.md or brief F4, otherwise the cards will be read out as nothing even when the flag is on.
5. [minor] (ML-12 copy) The new Meds.tsx source line says cards are 'written by Bantay in plain words from DailyMed, openFDA and NIH Office of Dietary Supplements'. It repeats the cards.json sources claim from round 1. Nothing in the lane shows the cards were checked against those labels, and the round 1 recipe values were admitted to be from memory. The cards are flag-gated pending clinician sign-off, so this is not yet user-facing. The clinician review must confirm the source claim before the flag is turned on.
6. [minor] (ML-17 tests) No test covers the new cook-mode behaviour: inert on #root, focus moved into the dialog, Escape leaving to the recipe, and inert removed on unmount. The builder disclosed this. A test of that cleanup and of the unknown-id path would have caught the inert lock above.
7. [minor] (ML-20 tests) Full vitest was not run by the builder or by this audit. The expected 'migration 0041/0042 not in KNOWN_MIGRATIONS' failure and the pushManifest/sensors import failures were not quoted. Only src/features/discover was run (29 pass).
8. [minor] (ML-17 tests) These round 1 minors are still open, as the builder disclosed. #2: the bundle test measures JSON length only, not dist chunk growth. #9: learn.medcards has no toggle or sync. #10: Meds lists live ldb.medications rows for archived people.
