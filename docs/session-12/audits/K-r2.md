# Lane K audit round 2 (Opus): pass_with_issues

1. [major] (ML-32 gate) Confirmed independently. A rerun of s12-core (PW_PORT=5608, S12_SHOTS=scratchpad\Kshots) gave 5 of 10 PNGs that are not byte-identical to the committed docs/session-12/shots/K: simple-today-light/dark, simple-today-calm-light/dark and today-full-dark. The brief item 'make shots reproducible' is still unmet. The builder reported this honestly as ML-32 ok:false and status partial. Likely cause: settle() reads window.scrollY/document.scrollingElement, but the committed and rerun simple-today shots are both at scroll top. If the app scrolls an inner container, the 'held still' check passes trivially and does not prove anything.
2. [minor] (ML-37 spec) False ok. The builder says the 'simple-today shots scroll to the BP tile', but committed simple-today-light.png (and my rerun) shows the top of the screen: Losartan card, Hold for help, Call 911, How are you?, Call Ate Joy. Neither shows the BP tile, which is the new feature, so the scroll-to-bottom in settle(page, true) has no visible effect. The new member-today-denied card ('Ask <first> to share with you') also has no shot. In e2e the user is signed out, so canViewReport always returns true.
3. [minor] (ML-12 copy) MemberPage access gate offline: getMember() runs live app_roles/people queries. When these fail offline it returns personId null and role 'member' without throwing. On their own member page (ownId '') or as an admin who is not in the cached carers list, the viewer then gets 'Ask <first> to share with you' even though they can see the data. Carers are fine because loadCarerOf falls back to the kv cache. Report has the same gate, so the bug is inherited, but the member page used to show the local Today card offline (partial ML-13 regression for self and admin).
4. [minor] (ML-09 invariant) In actions.ts logFeeling, any non-Unwell mood, including 'Not great', deletes the queued mood.unsent Unwell. Audit minor 6 asked only for Great/OK to supersede it. An elder who was Unwell offline and then taps Not great means the family is never told about the Unwell, and no toast says so. The test only covers 'ok'.
5. [minor] (ML-12 copy) isNetwork() treats any error that has a code, or a message without fetch/network/load failed/timeout, as 'refused'. That includes a Supabase 5xx or paused-project body and a 401 from an access token that expired while the phone was offline (the auto-refresh has not run yet on the reconnect retry). The queued Unwell is then deleted for good. The copy ('Your family was not told. Call them.') is honest, so this is not a false reassurance, but transient server failures lose the retry.
6. [minor] (ML-04 spec) Still open, as the builder reported: the Rev 2 item 4 overlap e2e (Jack button vs SOS at 360 and 390 px) needs F1 and the merged branch.
7. [minor] (ML-25 tests) Still open, as the builder reported: the spec was not proven with --repeat-each under 2 and 4 workers. The negative RPC check now uses waitForLoadState('networkidle'), which is an indirect proxy, not the app's own settled state.
8. [minor] (NEW other) retryUnsentMood is now single-flight, but Today.tsx 'go' runs notify(retryToast(r)) for each caller. A concurrent mount and online event still calls notify twice with the same text. This is harmless because setToast is idempotent for the same string, and there is no test at the Today level.
