# Lane C audit round 1 (Opus): fail

1. [blocker] (ML-16 tests) The DigestToggle switch can never save. DigestToggle.tsx:43 calls supabase.from('carer_prefs').upsert({user_id, digest_on, updated_at}, {onConflict:'user_id'}). PostgREST sends this as merge-duplicates: ON CONFLICT (user_id) DO UPDATE SET user_id = EXCLUDED.user_id, digest_on = ..., updated_at = .... But 0039 grants update only on (digest_on, updated_at), so Postgres checks UPDATE on user_id at plan time and refuses with 42501. I ran that exact SQL shape as authenticated (sub c1) on WSL db bantay_s12_c_aud after the lane rehearsal: 'ERROR: permission denied for table carer_prefs' on an empty table and again on an existing row. Every tap reverts the switch and shows 'Could not save', so the D-83 opt-out cannot be turned on. The rehearsal's 'the app upsert works' PASS (marked_by_digest_rehearsal.sql:74) tests a hand-written DO UPDATE SET digest_on, updated_at, not what the app sends. The vitest mock upsert always succeeds. Fix: grant update (user_id, digest_on, updated_at); the RLS with check user_id = auth.uid() already pins it. Or do an insert then an update without upsert. Then rehearse the PostgREST shape. Caveat: the shape comes from PostgREST's MergeDuplicates query builder, which puts every payload column in SET. I did not run a live PostgREST.
2. [major] (NEW safety) isVaccine (logic.ts:485) matches 'vaccin\p{L}*', so 'Vaccinium' counts as a vaccine. node check: 'Cranberry (Vaccinium macrocarpon) 500 mg' gives true, and so does 'Bilberry Vaccinium myrtillus'. Cranberry and bilberry capsules are common daily supplements for older people. Those rows would get no dose_missed alert, no review_open, and no 8 PM open-dose entry. That silently removes a safety alert, which goes against the doc's claim 'A normal medicine name never contains these words'. Narrow the rule to vaccine|vaccines|vaccination|vaccinations, and add the Vaccinium names to the negative test list.

8. [minor] (ML-07 privacy) meds_taken.marked_by_name copies the marker's first name onto every dose row. Anyone who can read the person's doses can read it, including read-only carers who people_read RLS would not let read the marker's people row. The name survives erasure of the marker's account (the FK nulls marked_by, not marked_by_name). This deviates from 'no new column beyond marked_by' and is disclosed. It needs a privacy sign-off, or the erasure should also null marked_by_name.
