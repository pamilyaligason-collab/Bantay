# Lane K audit round 1 (Opus): pass_with_issues

1. [major] (ML-12 copy) src/features/family/MemberPage.tsx MemberToday has no access gate, while Report.tsx does (useReportAccess). If a member does not share with the viewer, the member page still shows a Today card that says '<first> has not said how they feel yet' and 'No blood pressure saved yet'. That is untrue. The viewer simply cannot see those rows (R1/RLS), so a carer is falsely reassured about someone's safety state. Fix: gate the card, or say 'Not shared with you'.
2. [minor] (ML-12 copy) actions.ts: raise() maps every RPC error to 'offline', including 42501, an error:true from a null client and a server signed out. So an online user whose alert was refused is told 'Saved. We will tell them when you are online.' retryUnsentMood then retries silently and drops the alert after 24 h (UNSENT_MAX_MS) without telling anyone. The old toast's 'or call them' fallback for an unwell elder was also removed. The brief named this toast text, but the toast promises more than the code does when the failure is permanent.
3. [minor] (ML-32 gate) I re-ran the spec with S12_SHOTS pointed at the scratchpad. 4 of the 10 committed PNGs are not byte-identical: today-full-light, today-full-dark, simple-today-dark and simple-today-calm-dark. The today-full shot is taken with no settle wait, and the weather card is caught mid-reveal (faded title). The builder honestly reported ML-32 ok:false. The builder also claimed 14 shots, but only 10 exist in docs/session-12/shots/K.
4. [minor] (ML-04 spec) Rev 2 item 4 requires an overlap e2e for the Jack button against SOS at 360 and 390 px. K proves only DOM order in jsdom (Today.simple.test), with no geometric check. A fixed floating Jack button can still cover the mid-page SOS at some scroll positions, so the code comment 'must never cover it' is unproven. Needs an F1/orchestrator overlap e2e on the merged branch.
5. [minor] (ML-09 invariant) In NextUp.tsx, success requires markTaken(...) === keep.length. If a ticked dose was logged meanwhile (another phone or tab), the remaining rows are saved but the toast shows FAIL_TEXT.failed ('Could not save'). Today.tsx can also run retryUnsentMood twice at once (mount plus the online event): 2 RPCs and possibly 2 toasts. The server dedupes per day, so this is harmless but untested.
6. [minor] (NEW invariant) A queued 'unwell' in kv mood.unsent is still raised on reconnect even if the person has since logged Great or OK. No later mood clears or supersedes the queued alert, and no test covers it.
7. [minor] (ML-17 tests) The MemberPage.test.tsx render test runs on the wall clock and asserts /Aspirin.*12:01 AM.*(Missed|Due now|Later)/, which accepts any outcome. The hand-computed todayView tests cover the logic, but the rendered dose word is not pinned.
8. [minor] (ML-25 tests) e2e/s12-core.auth.spec.ts uses page.waitForTimeout(300) for the negative RPC-count check after reload, plus 400 ms waits before shots. It was not proven with --repeat-each under 2 and 4 workers.
